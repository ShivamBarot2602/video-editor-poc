One video in, every social format out.

A redesign direction for the SocialPilot video tool. Today it is six separate experiments behind one nav bar. This proposal turns it into a single studio where a video is the project, and captions, clips, thumbnails and reframing are tools that work on it and feed each other.

Scope app/client, every route Covers information architecture, design system, 6 key screens, rollout Status proposal for review
What the current app tells a first-time user

The features are solid. The product around them is missing.

Each tool was built as its own POC with its own layout, upload box and visual rules. Nothing tells the user that the video they just captioned is the same one they can clip, thumbnail and reframe. These numbers come straight from app/client/src.

5 upload boxes

Home, Clips, Thumbnails, Playground and SmartCrop each start with their own upload. The user re-picks the same video on every tool.

2 design languages

SmartCrop runs a forced-black theme with white pill buttons and its own --sc-* tokens. Crossing into it feels like leaving the app.

492 inline style blocks

Most layout and type lives in style={{…}}, so spacing, sizes and colors drift from page to page.

129 text sizes of 9–11px

Everything is set in IBM Plex Mono at 10–12px. It reads like a terminal, not a creative tool, and is hard to scan.

7 top-level nav items

Upload, Playground, Thumbnails, Clips, SmartCrop, Docs and Sign out sit at equal weight. Internal lab tools look like product features.

0 shared progress pattern

Transcribe, burn, clip export, thumbnail generation and render each report progress differently: toasts, inline bars, overlays, modals.

Information architecture

Make the video the project, and the features its tools.

Every feature already takes a videoId. The redesign makes that explicit: open a video once, then move between tools with tabs that keep the same header, the same player and the same job status.

Design principles

Quiet chrome, a dark stage, and status you can read from across the room.

The footage is the loudest thing on screen

Chrome follows the light or dark theme, but video always sits on a dark stage, like a monitor in an edit bay. Subtitle colors, crops and thumbnails are judged against real contrast in both themes.

One tally color means "working"

Amber, borrowed from a camera's tally light, marks anything in progress across the app: transcribing, burning, rendering. Green is done, red is failed, and the brand blue is reserved for actions and selection.

Tools hand off to each other

A clip has a "Reframe to 9:16" action. A reframed short can open in Captions. Each hand-off keeps the same project, so the user builds a set of outputs instead of starting over.

Talk about results, not models

Users pick "Watch the video" or "Read the transcript", not gemini-2.5-flash. Model names, costs and provider comparisons move to the Lab, where the team needs them.

Timecode is the one place for monospace

UI text is set in a proportional sans at 13px and up. Mono appears only for timecodes and durations, where columns of digits have to line up.

Presets first, controls second

Captions open on four style presets. The full style panel is still there for fine-tuning, but most videos should be styled in one click.

Design system

One token set for every screen, SmartCrop included.

Same token names as today's index.css where possible so the migration is mostly value changes. The --sc-* set is retired. This page itself uses the system, so switching your theme shows both palettes.

Rollout

Five steps, each shippable on its own.

No backend changes are needed until step 4. The order puts the shared foundation first so every later screen is cheaper to build.

Before building

Four calls that change the plan.

Product name in the UI

"SP Video Editor POC" undersells it. Options are SocialPilot Studio, or no name at all inside the SocialPilot app.

Suggested: SocialPilot Studio

Default theme

Today light is the default. Video tools usually default dark, but SocialPilot's main app is light.

Suggested: light chrome, dark stage, matching the parent app

Who sees the Lab

Playground, model choice and provider reports are useful to the team but confusing to customers.

Suggested: Lab behind a team flag

Reframe from library videos

Folding SmartCrop into the project needs a small server change so it reuses the uploaded file.

Suggested: do it in step 4, keep the separate upload until then
